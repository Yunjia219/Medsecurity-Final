⚠ FHIR 標準一致性提醒

  • README.md 宣稱核心 FHIR Resources 為 MedicationRequest、Bundle、Patient，但實際程式碼中寫入的是 MedicationStatement 與 Flag（見 patient.html 約 707-757 行），並無任何一處建立 MedicationRequest。若競賽評審依 README 核對 Resource 使用，建議二擇一：更新 README 說明實際用到的 Resource，或補上 MedicationRequest 的建立流程（例如醫師端「開立處方」改為真實 POST）。
  • 四個端口中只有病患端會真的打公用 HAPI FHIR 測試伺服器（hapi.fhir.org/baseR4），醫師端、管理員端皆為假裝連線的 UI 效果。若要在簡報中呈現「跨角色 FHIR 整合」，這個落差可能被問到。
  • 目前無任何後端／資料庫，所有寫入操作除了打公用 HAPI 伺服器外都不持久化，重新整理頁面即恢復成 mockData 初始狀態。
